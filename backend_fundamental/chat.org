  ### Phase 1: Finding the Server (DNS)
    *   Trying 54.160.105.28:443...
  • The Problem: The internet doesn't route by domain names like httpbin.org. Routers only understand IP addresses (like 54.160.105.28).
  • What happens: Your computer automatically calls a DNS (Domain Name System) server—the "phonebook" of the internet—and asks: "What is the
  IP address of httpbin.org?" Once it gets 54.160.105.28, it dials that address.
  ──────
  ### Phase 2: Connecting the Wire (TCP Handshake)
    * Connected to httpbin.org (54.160.105.28) port 443 (#0)
  • Port 443: An IP address gets you to the computer; a Port gets you to the specific program running on it.
      • Port 80 is standard for unencrypted web traffic (http://).
      • Port 443 is standard for encrypted web traffic (https://).
  • TCP Connection: Your computer and the server perform a 3-way handshake (SYN → SYN-ACK → ACK):
      1. Your computer: "Hey, can we talk?"
      2. Server: "Yes, I can hear you. Can you hear me?"
      3. Your computer: "Yes, let's talk."
      Now a reliable two-way pipe is open.
  ──────
  ### Phase 3: The Secret Handshake (TLS / SSL Encryption)

  Because you typed https:// (the S stands for Secure), everything must be encrypted so nobody on your Wi-Fi or ISP can spy on your data.

    * ALPN, offering h2, http/1.1
  • ALPN (Application-Layer Protocol Negotiation): Your computer tells the server: "I can speak modern HTTP/2 (h2) or older HTTP/1.1. Which
  do you prefer?"
    * Server certificate:
    *  subject: CN=httpbin.org
    *  start date: ...
    *  expire date: ...
    *  issuer: ...
    *  SSL certificate verify ok.
  • ID Card Check: Before sending any data, your computer asks the server for proof of identity. The server shows a digital certificate
  issued by a trusted authority (Certificate Authority).
  • Your computer verifies:
      1. Is the certificate expired? No.
      2. Does the certificate match httpbin.org? Yes.
      3. Is the signature valid? Yes (verify ok).

    * SSL connection using TLSv1.3 / ...
  • The Keys: Both sides agree on an encryption key using math (TLS 1.3). From this moment on, everything sent over the wire is scrambled
  garbage to anyone eavesdropping.
  ──────
  ### Phase 4: The Actual HTTP Conversation
  Now that the secure pipe is open, the actual HTTP messages are sent.
  #### 1. What your machine sent (> Lines - The Request):
    > GET /get HTTP/2
    > Host: httpbin.org
    > User-Agent: curl/7.81.0
    > Accept: */*
    >

  • GET /get HTTP/2 → The Request Line.
      • GET: The action (I just want to retrieve data).
      • /get: The path (the specific page/endpoint on the server).
      • HTTP/2: The version of the protocol being used.
  • Host: httpbin.org → Tells the server which website you want (a single physical server can host hundreds of different websites).
  • User-Agent: curl/... → Identifies who is making the request (e.g., curl, or Mozilla Chrome, or an iPhone app).
  • Accept: */* → Tells the server: "I can accept any format you send back (JSON, HTML, text, etc.)."
  • Empty Line (>) → Signals the end of the request headers.
  ──────
  #### 2. What the server sent back (< Lines - The Response):
    < HTTP/2 200
    < date: ...
    < content-type: application/json
    < content-length: 300
    < server: gunicorn/...
    <
  • HTTP/2 200 → The Status Line. 200 means OK (success).
  • content-type: application/json → The server warns your computer: "The body I am about to send you is formatted as JSON."
  • content-length: 300 → The exact size of the payload in bytes.
  • server: gunicorn/... → The backend web server software running on their machine (Gunicorn is a Python WSGI server!).
  • Empty Line (<) → Signals the end of headers.
  ──────
  #### 3. The Body (The Payload):

  Right after the empty line < , the server dumps the raw data:

    {
      "args": {},
      "headers": {
        "Accept": "*/*",
        "Host": "httpbin.org",
	"User-Agent": "curl/7.81.0"
  	},
  	"origin": "YOUR_IP_ADDRESS",
      "url": "https://httpbin.org/get"
    }

  httpbin is a mirror server—it literally takes the headers your computer sent and packages them into a JSON object to show you what it
  received.
  ──────
  ### Phase 5: Wrapping Up

    * Connection #0 to host httpbin.org left intact

  • In older days (HTTP/1.0), the connection was closed immediately after one request.
  • Modern web keeps the TCP connection alive so if your browser needs to download an image or CSS next, it doesn't have to repeat the DNS
  and Handshake steps all over again.
